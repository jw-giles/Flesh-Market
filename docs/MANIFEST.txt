## 1.3.1 changes (drawChart retry loop while hidden; CLIENT)
- ROOT CAUSE, core.js drawChart(): `if (W < 10 || H < 10) { setTimeout(drawChart, 100); return; }`. W and H come from `canvas.clientWidth/clientHeight`, which are 0 for any element inside a `display:none` ancestor. #chart lives inside #marketTab, which is display:none on every other tab. So "not laid out yet" and "tab is hidden" were indistinguishable to this branch.
- WHY IT ACCUMULATED: _pushWave() (core.js ~4013) schedules drawChart through requestAnimationFrame on EVERY price tick, with no visibility test. Each tick that lands on the hidden branch starts an independent 100ms self rescheduling chain. They are separate setTimeout chains, not deduped, and none terminate until the canvas is visible. Time spent on another tab is directly proportional to the number of live chains.
- BACKGROUNDED TABS MAKE IT WORSE: requestAnimationFrame is throttled to zero when the page is hidden, so no NEW chains start, but setTimeout keeps firing, so every chain already started keeps running with the screen off. Each iteration does getContext, two canvas dimension writes and a ctx.scale before bailing.
- PRE-EXISTING, NOT INTRODUCED BY 1.3.0. Desktop hits it the same way. It is listed here because the shell changes the exposure: a phone player is off Market by default.
- FIX: `if (canvas.offsetParent !== null) setTimeout(drawChart, 100);`. offsetParent is null iff an ancestor is display:none (it is also null for position:fixed elements, which #chart is not; do not copy this guard to a fixed element without checking). The genuine "visible but not yet laid out" case still retries, because offsetParent is non-null there.
- COME-BACK PATH: core.js ~4026 already has `new ResizeObserver(() => { if (_waveBuffer.length) drawChart(); }).observe(_chartCanvas)`. That was the ONLY thing covering display:none -> block, which was the open question at the end of 1.3.0. mobile.js render() now calls nudgeChart() on the next animation frame when the visible view is market or board/heat. Belt and braces on purpose: RO firing for a display change is correct in Chrome and Safari but it is a single point of failure for a surface the player looks at first.
- NOT CHANGED: _pushWave still schedules on every tick. An early out there would be a second place that has to know about visibility, and the guarded drawChart already costs almost nothing when hidden. If profiling later says otherwise, the early out belongs in _pushWave, not another guard in drawChart.
- OTHER CANVASES CHECKED, NONE AFFECTED: _drawDonut, _drawBarsAxis and drawEquity all bail with a plain `return` when their element is missing or empty. drawChart was the only one with a timer retry.
- tools/mobile-check.mjs 71 -> 76. Three source assertions (guard present, unguarded form absent, nudgeChart present) and two live ones (entering Market redraws, leaving Market does not). ## 1.6.3.0 changes (Corruption skims the bill; siege stores; NPC churn; migration rehearsed; SERVER)
- CORRUPTION -> CIVIC BILL. civicBill split into civicBillBase (unchanged formula) and civicBill = base * (1 + billSkim(d)). billSkim = BILL_SKIM_MAX(0.45) * max(0, s_corruption - BILL_SKIM_FLOOR(20)) / (SCALAR_MAX - FLOOR). Checked monotonic across 0..100 so a mayor can never make the bill cheaper by getting more corrupt. districtSummary exposes billBase and skim; the panel itemises them.
- SIEGE STORES. Three additive REAL columns on city_districts (stock_food/med/tech), guarded ALTER, added to DISTRICT_COLS allowlist. New msg city_stock {colonyId, district, cls, weeks}; mayor only, blocked by arrears, capped at stockCapacity = stockWeekUnits * STOCK_MAX_WK(6), priced at STOCK_UNIT_COST(240k)/unit.
- UNITS, the trap: demand and local in civicPressure are RATES (per week); a stockpile is a QUANTITY. First cut did `local += stockOf(...)`, so 6 weeks of cover read as 6 weeks of production EVERY week and took a besieged unzoned world from pressure +2.50 to -2.50. FIX: `local += min(held, max(0, demand - local))`. Full cover now lands a siege at exactly 0.00.
- SCOPE, the second trap: stockWeekUnits is a DISTRICT's share (colony demand / districtCount) and is what sizes and prices a purchase; cover has to be REPORTED against colonyWeekUnits (whole colony demand). Reporting one in the other's units showed 84 weeks of cover for what was really 6. New export colonyWeekUnits; cityFullData.stock uses perDistrict for weekCost and perColony for weeks.
- DRAWDOWN. drawStock(colonyId, dtWeeks) runs once per COLONY per tick, not per district, because the shortfall cover meets is a colony-level number. factor = (1 - eaten/held) * (1 - spoil) where eaten = min(held, shortfallUnits*dt) and spoil = STOCK_DECAY_WK(0.14)*dt. New export shortfallUnits(colonyId, cls) = max(0, demand - local) ignoring stores. A colony that is not short loses only spoilage. Full stores under permanent siege last ~3 weeks, not 6, because spoilage compounds with consumption.
- NPC CHURN. churnNpcShops(colonyId, d, dtWeeks) called from the tick immediately before ensureNpcShops, so it is a replacement rate not a drain. rate = (CHURN_BASE_WK 0.010 + CHURN_STRESS_WK 0.055 * stress) * dt, stress = unrest*0.6 + crime*0.4 normalised. Fractional expectation resolved by a coin flip so a thin district still turns over occasionally. Oldest first. Floor of 4 firms. Single-tick cap of 25% of the district. MEASURED: 0.51 firms/wk of 40 calm, 2.48 at unrest+crime 95.
- MIGRATION REHEARSAL, first time this has been done. ## 1.2.7.0 changes (Storefronts: tenancy layer opens the closed city; SERVER + CLIENT)
- WHY: 4,788 lots exist in the entire game (new_anchor 253) against an 8,000 concurrency target, and the one-lot cap made that a hard ceiling, not a price. Fix is vertical, not horizontal: ground stays finite (the fraction gates that drive the stage ladder need a finite denominator, and war needs a defined target), floor space does not.

- DEMAND: commercialPool = book x COMMERCE_PCT_WK(0.0022) x prosperity/70 x output/70, so the pie scales with development instead of being fixed and split (this was the correction to the first design pass, where pop-scaled demand barely grew: POP_BOOK_K moves new_anchor 820M->882M across a F52B build, under 8%). NPC market is ALWAYS a counterparty; scarcity is in the appetite, never in finding a buyer, and it moves over weeks not ticks.

(3) Per-player decay: share weight = lotTier / sqrt(nth shop that player holds in that city), applied as a WEIGHT INSIDE the pool so the pool conserves.
